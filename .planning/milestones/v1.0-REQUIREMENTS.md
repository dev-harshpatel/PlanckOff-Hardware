## v1 Requirements

### PDF Beautification

- [ ] **PDF-01**: All PDF exports share one visual template — identical fonts, colors, spacing, and table style across door schedule, hardware sets, pricing, and submittal package
- [ ] **PDF-02**: Every PDF has a branded header with company logo, project name, and export date
- [ ] **PDF-03**: Every PDF has a footer with page numbers
- [ ] **PDF-04**: PDF tables have clear column headers with styled background
- [ ] **PDF-05**: PDF table rows have alternating row shading for readability
- [ ] **PDF-06**: Multi-page PDFs repeat column headers on each new page
- [ ] **PDF-07**: No rows are cut off mid-record at page boundaries — pagination is clean

### Excel Beautification

- [ ] **XLS-01**: All Excel exports have bold, colored column header rows
- [ ] **XLS-02**: Column widths are set based on content type — no truncation of values
- [ ] **XLS-03**: The header row is frozen so it stays visible when scrolling large sheets

### Sequential Ordering

- [ ] **ORD-01**: The data array passed to PDF generators preserves the exact order from the UI / final JSON — no implicit sorting or reordering
- [ ] **ORD-02**: The data array passed to Excel generators preserves the exact order from the UI / final JSON
- [ ] **ORD-03**: If the user has applied a custom sort in the UI, that order is reflected in all exports
- [ ] **ORD-04**: Export layer has explicit order-preservation logic as a safety net (index-based or explicit orderBy)

### Verification

- [ ] **VER-01**: All requirements verified across at least 3 export types: Door Schedule, Hardware Sets, Pricing

### Error Message Registry

- [ ] **ERR-01**: A `constants/errors/` directory contains domain-specific error files (`auth.ts`, `doors.ts`, `hardware.ts`, `pdf.ts`, `general.ts`) — each exporting typed error objects with `code`, `message`, and optional `action` fields
- [x] **ERR-02**: No hardcoded inline error strings exist outside the registry in components, hooks, or services
- [x] **ERR-03**: Every known failure point (auth, API, validation, file upload, AI extraction) maps to a named registry entry
- [x] **ERR-04**: A reusable `<ErrorDisplay>` component renders any registry error consistently using the application's Tailwind/shadcn theme
- [ ] **ERR-05**: Unhandled/unexpected errors fall back to a generic registry entry — raw JS error messages and stack traces are never shown to users
- [x] **ERR-06**: All existing error surfaces (toasts, inline form errors, modal errors, page banners) use the registry exclusively
- [ ] **ERR-07**: Adding or updating an error message requires changing only the relevant file in `constants/errors/`

### Pricing Report Filtering Fix

- [x] **PRF-01**: Level-wise filter selections in the Pricing Report return only the hardware/pricing rows that belong to the selected level(s)
- [x] **PRF-02**: The count displayed in the Pricing Report equals the sum of the `Total Qty` column for the filtered/grouped result, not the number of visible rows
- [x] **PRF-03**: Mixed Use Kamloops project displays correct level-wise filtered data with accurate quantity counts
- [x] **PRF-04**: Total Qty values remain accurate after applying level filters
- [x] **PRF-05**: Pricing totals (subtotals and grand totals) remain accurate after applying level filters
- [x] **PRF-06**: Exported Excel/PDF Pricing Report data matches the filtered UI result exactly
- [x] **PRF-07**: Detail modal quantities and totals match the main Pricing Report table after filtering
- [x] **PRF-08**: Existing pricing report behavior without filters continues to work (no regression)

### Real-Time UI Updates

- [x] **RT-08**: The `supabase_realtime` publication includes `project_pricing_items`, `project_pricing_proposal`, and `projects` (migration 019) — prerequisite for all other RT requirements
- [ ] **RT-01**: Any update made by the user is reflected in the UI instantly without a page reload or manual re-fetch
- [ ] **RT-02**: In a multi-tab scenario, a change made in Tab A is automatically reflected in Tab B within 1–2 seconds
- [x] **RT-03**: Optimistic updates roll back cleanly if the server write fails, with an appropriate error message shown
- [ ] **RT-04**: No stale subscriptions or memory leaks on navigation between pages
- [ ] **RT-05**: Works correctly alongside any caching layer — cached data does not override a fresh Realtime update
- [ ] **RT-06**: Subscription reconnection on network drop is handled gracefully (no manual reload needed)
- [x] **RT-07**: Self-event filtering prevents echo updates — user's own writes don't trigger a redundant re-render
