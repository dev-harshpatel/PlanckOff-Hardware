<objective>
Wire Realtime in-memory patching for `project_hardware_finals` (hardware sets + doors) and add the dedup-mark side of the loop. This is the first of two "callback-implementation" plans (the second, 04-06, covers pricing + projects).

The two ends of the loop:

1. **Reader (useProjectData.ts):** Add an `onHardwareFinalsChange` callback that:
   - Calls `isOwnWrite('project_hardware_finals', payload.new.id, payload.new.updated_at)` and returns early if true
   - Skips DELETE events (per RESEARCH.md table 1)
   - Pulls `payload.new.final_json`, runs `transformFromFinalJson`, sets `hasFinalJsonRef.current = true`, sets `isInitialMount.current = true` (suppress auto-save loop), then calls `setHardwareSets` and `setDoors`
   - Also adds an `onFullReload` callback (for reconnect recovery) that re-runs the existing `loadProjectData` flow — implemented as a `reloadAllProjectData` callback exported from the hook

2. **Writer (useProjectPersistence.ts):** After `saveToFinalJson` PUTs successfully, read `data.updatedAt` and `data.id` from the response and call `markPendingWrite('project_hardware_finals', id, updated_at)`.

Purpose:
- RT-01: User edits in this tab persist (existing) and external edits propagate via Realtime (new).
- RT-03: The pattern enables Plan 04-07 to layer optimistic updates on top.
- RT-05: With no SWR/React Query in this codebase, the in-memory patch IS the cache update — no stale read possible.

Output: Two updated hook files, both compile.
</objective>
