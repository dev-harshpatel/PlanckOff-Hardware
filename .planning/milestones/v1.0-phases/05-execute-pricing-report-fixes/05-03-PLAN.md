**Step 1 — Open the Mixed Use Kamloops project**
1. Visit http://localhost:3000 and sign in if prompted.
2. Open the Mixed Use Kamloops project. If the project is missing, upload the source Excel via the standard upload flow first.
3. Navigate to the Pricing Report tab/page. Wait for the data to load (skeleton clears).

**Step 2 — Verify filter dropdown is populated (PRF-01, PRF-03)**
4. Locate the Building Location filter (multi-select dropdown).
5. Open it. Confirm the options include `LEVEL 01` and `LEVEL 02`. Record the exact option strings.
   - Expected: at least `LEVEL 01` and `LEVEL 02`.
   - If empty: STOP. Two possible causes: (a) the project loaded via DB path before 05-02 was in effect — re-load the page now and re-test. (b) the source upload doesn't use BUILDINGN AREA / BUILDING AREA / BUILDINGLOCATION columns — inspect the source Excel and re-test against a fresh upload.

**Step 3 — Verify LEVEL 01 filter (PRF-01, PRF-02, PRF-03, PRF-04, PRF-05)**
6. Select only `LEVEL 01` in Building Location. Deselect anything else.
7. On the Doors tab, record:
   - Count badge value (e.g., "Doors (4)").
   - Visible row count.
   - SUM of the "Total Qty" column across visible rows.
   - Pricing subtotal (Total Price) value.
8. Expected (per RESEARCH.md): badge = 4, rows = 4, Total Qty sum = 4, subtotal = SUM(g.unitPrice * g.totalQty) for the 4 matching groups.
9. On the Frames tab, record the same four values. (May be 0 if no frames at LEVEL 01.)

**Step 4 — Verify detail modal consistency (PRF-07)**
10. Still LEVEL 01 filtered. On Doors tab, click any door row to open the detail modal.
11. Record the door tags shown in the modal and the modal's Total Qty / Total Price values.
12. Confirm every door tag in the modal also appears in the underlying group's row in the filtered table.
13. Confirm NO door from LEVEL 02 appears in the modal.
14. Confirm modal totals match the same row's totals on the main table.
15. Close the modal.

**Step 5 — Verify LEVEL 02 filter**
16. Change Building Location filter to only `LEVEL 02`.
17. On the Doors tab, record: badge value, row count, Total Qty sum.
18. Expected: badge = 41, rows = 41, Total Qty sum = 41 (all qty=1 in Kamloops).

**Step 6 — Verify export with filter active (PRF-06)**
19. With LEVEL 02 selected, click the Excel export button (Doors tab). Save the file.
20. Open the exported XLSX. Count data rows (excluding header).
21. Expected: 41 rows. Record exact count.
22. Click the PDF export button. Open the PDF.
23. Visually confirm the PDF table contains only LEVEL 02 doors. No LEVEL 01 doors should appear.

**Step 7 — Verify no-filter regression (PRF-08)**
24. Clear all filters (deselect both LEVEL 01 and LEVEL 02). Confirm the dropdown shows "All" or empty selection.
25. Record the Doors count badge. Expected: equals SUM of Total Qty across the entire project (45 if all qty=1; may differ if any door has qty > 1).
26. Compare to the project's known SUM(Total Qty) from the Door Schedule view (or sum the source Excel "Total Qty" column).
27. Confirm: badge value === Door Schedule total. If they differ, capture the gap and STOP.
28. Click Excel export with no filter. Confirm exported row count === sum of `g.doors.length` across all groups (this is the count of Door records / groups, NOT the qty-weighted count — the export emits one row per group).

**Step 8 — Verify hardware tab (regression for hardware re-grouping)**
29. Switch to the Hardware tab with no filter active. Confirm count badge looks reasonable.
30. Apply LEVEL 01 filter. Confirm Hardware tab shows only hardware items associated with LEVEL 01 doors (since plans 05-01 re-groups hardware from `filteredDoorsForHw`).

**Step 9 — Capture results**
31. Record all observed values in `.planning/phases/05-execute-pricing-report-fixes/05-03-SUMMARY.md`. Use the template below.
32. Mark each PRF requirement PASS / FAIL based on observations.
