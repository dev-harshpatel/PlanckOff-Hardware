<objective>
Fix the pricing page data-source bug identified in the v1.0 audit. Currently `app/project/[id]/reports/pricing/page.tsx` loads doors via `transformDoors(dsJson.data.scheduleJson, sets)` — the raw schedule JSON path — which is the WRONG authoritative source. User edits to `buildingLocation` / `buildingTag` are saved to `finalJson` (via the hardware merge), not back to `scheduleJson`, so the level filter never sees user edits.

The fix: when `finalData` exists, use `transformFromFinalJson(finalData).doors` as the door source. Also patch the `transformFromFinalJson` buildingLocation chain at `utils/hardwareTransformers.ts:309` to fall back to `door.buildingArea` — same pattern as the already-committed `transformDoors` fix at line 169.

Purpose: Close PRF-03 (Mixed Use Kamloops sees correct level-wise data) and the data-source half of PRF-01 (level-wise filter selections return rows belonging to selected levels for all loaded projects — both fresh uploads and DB-loaded with user edits).

Output: Two file edits (page.tsx restructure of the `load()` function; hardwareTransformers.ts one-line addition to the buildingLocation chain) and a SUMMARY.md.
</objective>
