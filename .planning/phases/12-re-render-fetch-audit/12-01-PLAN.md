<objective>
Eliminate re-fetch-after-write in `addProject` and `restoreProjectFn` (PERF-03), and stop wide re-renders across all 6 useProject() consumers caused by unstable callback identities on every ProjectProvider render (PERF-01).

Purpose: ProjectContext is the highest-impact PERF target — its current state causes 6 different consumers (`app/page.tsx`, `app/project/[id]/page.tsx`, `app/project/[id]/reports/layout.tsx`, `app/project/[id]/reports/page.tsx`, `app/project/[id]/reports/submittal-package/page.tsx`, `components/layout/AppShell.tsx`) to re-render on every internal state change because the action callbacks are recreated as new function references on every render and the provider value is a fresh object literal every render. Additionally `addProject` and `restoreProjectFn` each fire a full `GET /api/projects` after writes, doubling the Supabase read volume on every project create/restore.

Output: `contexts/ProjectContext.tsx` with all 8 action callbacks wrapped in `useCallback`, the Provider value wrapped in `useMemo`, and `fetchProjects()` calls removed from `addProject` and `restoreProjectFn` (replaced with local `setProjects` mutations). Zero behavior change — same toasts, same realtime echo dedup, same domain-array preservation.
</objective>
